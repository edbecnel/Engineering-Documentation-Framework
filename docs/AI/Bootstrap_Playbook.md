## Purpose

This playbook enables AI assistants (Cursor, Copilot, etc.) to bootstrap EDF-compliant repositories reliably. It supplements the human-oriented [Bootstrap Guide](../Development/Bootstrap_Guide.md) with decision trees, file copy rules, prompt templates, and validation gates.

For the machine-readable interaction contract, see [edf.bootstrap.v1.yaml](../../interaction/specs/edf.bootstrap.v1.yaml) and [ADR-0004](../Architecture/ADRs/ADR-0004-Interaction-Specifications.md). Execute phases per the spec; do not embed methodology rules here that are not in the canonical guide.

For ongoing engineering work after adoption, see [Repository_Workflow.md](Repository_Workflow.md).

## AI Responsibilities During Bootstrap

- Read [Bootstrap Guide](../Development/Bootstrap_Guide.md) and this playbook before acting
- Confirm greenfield pattern with the human (fork EDF vs adopt into separate repo)
- Run bootstrap scripts from the local EDF clone; never assume scripts run from the target repo
- Produce complete files at normal repository paths
- Run Framework Advisor after structural changes
- Report limitations and ask before destructive or ambiguous actions

## Decision Tree — Greenfield Pattern

```text
User wants to bootstrap EDF?
│
├─ "Start from EDF template" / "fork this repo"
│     → Do NOT run create_canonical_structure on a fresh fork
│     → Customize PROJECT_CHARTER, PROJECT_INDEX, README, handbook content
│     → Copy ADOPTION_STATUS template; mark Bootstrap complete after customization
│
└─ "Adopt into my existing/empty repo"
      → Confirm local EDF clone path
      → Run: adopt-edf.sh bootstrap [--profile core|software-engineering] "/target"
      → Customize generated stubs per file copy rules below
```

## File Copy Rules

| Content | Action |
|---------|--------|
| Canonical folders | Created by `create_canonical_structure` — do not duplicate manually |
| `PROJECT_CHARTER`, `PROJECT_INDEX` | Edit generated stubs with project-specific content |
| `docs/AI/README.md` stub | Expand OR copy full handbook from EDF reference if team wants Reference Parity |
| Full AI handbook (`docs/AI/*.md`) | Copy from EDF only when user requests Reference Parity; customize project name and conventions |
| `docs/Governance/` | Not generated — copy from EDF incrementally when targeting Governed tier |
| `docs/Developer_Handbook/` | Skeleton provides 2 files — add chapters as project matures |
| `docs/Templates/` | Copy individual templates from EDF on demand; do not bulk-copy all templates |
| `ENGINEERING_DOCUMENTATION_FRAMEWORK.md` | Generated by bootstrap — do not overwrite if exists |

## Prompt Templates

### Phase 0 — Confirm scope

```text
I am bootstrapping EDF for [project name].

Greenfield pattern: [fork EDF template | adopt into separate repo at PATH]
EDF clone path: [PATH]
Profile: [software-engineering | core]
Target tier: [Bootstrap | Navigable | Governed | Reference Parity]

Read docs/Development/Bootstrap_Guide.md and docs/AI/Bootstrap_Playbook.md.
Confirm the plan before running scripts.
```

### Phase 1 — Run bootstrap

```text
From EDF clone [PATH], run:
  ./scripts/adopt-edf.sh bootstrap [--profile PROFILE] "[TARGET]"

Report script output. If chmod errors occur, run chmod +x scripts/*.sh first.
Do not modify existing files in TARGET except those created by scripts.
```

### Phase 2 — Customize identity

```text
Customize these files for [project name] with complete file replacements:
- PROJECT_CHARTER.md (mission, scope, stakeholders, constraints)
- PROJECT_INDEX.md (status, owners, documentation map)
- README.md (add link to PROJECT_INDEX.md)

Preserve breadcrumb navigation format used in EDF documents.
```

### Phase 3 — Validate

```text
Run conformance validation:
  ./scripts/adopt-edf.sh validate "[TARGET]"

Compare scores to docs/Development/Adopter_Conformance_Tiers.md for tier [TIER].
Summarize gaps and recommend next steps. Update ADOPTION_STATUS.md if present.
```

## Validation Gates

| Gate | Pass criteria |
|------|---------------|
| **G1 — Scripts** | `create_canonical_structure` and `generate_documentation_skeleton` exit 0 |
| **G2 — Structure** | Framework Advisor Structure score ≥ 80% (Bootstrap tier) |
| **G3 — Identity** | PROJECT_CHARTER and PROJECT_INDEX describe the actual project |
| **G4 — Navigation** | README links to PROJECT_INDEX |
| **G5 — Tier** | Overall score meets target tier in Adopter Conformance Tiers |

Do not mark bootstrap complete until G1–G4 pass. G5 may be deferred if human accepts a lower initial tier.

## Common Failure Modes

| Failure | Resolution |
|---------|------------|
| Permission denied on `.sh` | `chmod +x` in EDF clone `scripts/` |
| Wrong repo bootstrapped | Confirm target path; scripts are create-only so re-run is safe |
| Copied entire EDF repo when user wanted adoption | Revert; run bootstrap against user's repo instead |
| Expecting full AI handbook from skeleton | Copy handbook files from EDF or expand stub per copy rules |
| Governance score low on day one | Expected — adopters target Bootstrap/Navigable first |
